## 🔬 **Investigation Process**

### **What We Tried:**
1. ✅ **React.memo()** - Partial success (reduced unnecessary re-renders)
2. ✅ **Selection Set optimization** - Success (O(1) lookups)
3. ✅ **useMemo for renderedShapes** - Success (stable references)
4. ❌ **useCallback for App callbacks** - Failed (42% regression, reverted)
5. ✅ **Presence heartbeat fix** - **MAJOR SUCCESS** (460% improvement!)
6. ✅ **Debug logging removal** - No impact (confirmed not the bottleneck)

### **Key Learnings:**
1. **New reference = re-render** - Even if contents are identical
2. **State updates cascade** - One state change can trigger hundreds of re-renders
3. **useMemo only helps if dependencies are stable** - Unstable deps defeat the purpose
4. **Console logging has minimal impact** - Not a significant performance bottleneck
5. **Always track references** - Use refs to compare before setState
6. **Evidence-based optimization** - Logging revealed the exact problem

## ⚠️ **Known Limitations**

### **1. Multi-Select at 28 FPS (Not 60)**

**Why:**
- Creating 20 React elements on every selection change
- React reconciliation overhead
- Konva rendering selection UI (borders, handles)

**Status:** **Acceptable** - 28 FPS is functional (cinema is 24 FPS!)

**To improve further would require:**
- Canvas-level selection rendering (skip React)
- Virtual shapes (only render visible)
- More aggressive memoization

### **2. Sync Latency at 688ms (CRITICAL)**

**Problem:** Firestore writes take 688ms on average

**Impact:** Shapes feel laggy when creating/moving

**Next Priority:** Quick Win #4 (Debounced position updates)
