# 🎯 Performance Root Cause Analysis - Multi-Select FPS Drop

**Date**: October 19, 2025  
**Phase**: Phase 4a - Block 4 (Performance Optimization)  
**Issue**: Multi-select causes FPS to drop from 60 → 33 FPS

---

## 🔍 **Investigation Summary**

Added render logging to `App.tsx` and `Canvas.tsx` to track component re-renders and `useMemo` behavior.

### **Test Scenario**
1. Create 20 circles via AI
2. Multi-select 5 shapes (Shift+Click)
3. Monitor console logs

---

## 🚨 **Root Cause Identified**

### **Problem 1: Unstable Callback References**

The `useMemo` in `Canvas.tsx` depends on callback props from `App.tsx`:
```typescript
const renderedShapes = useMemo(() => {
  // Creates 20 shape components
}, [
  shapes,
  selectedShapeIds,
  onSelectShape,        // ❌ Recreated every render
  onShapeDragStart,     // ❌ Recreated every render
  onDuplicateShape,     // ❌ Recreated every render
  onShapeDragEnd,       // ❌ Recreated every render
  onUpdateShapePosition,
  onUpdateShapePositionAndDimensions,
  onUpdateShapeDimensions,
  onUpdateShapeProperties,
  onTextChange,         // ❌ Recreated every render
]);
```

**Evidence from logs:**
```
🎨 Canvas render #293 { shapeCount: 20, selectedCount: 1 }
🔨 useMemo re-ran - creating 20 shape elements    ← EVERY RENDER!
🎨 Canvas render #294 { shapeCount: 20, selectedCount: 1 }
🏠 App render #129 { shapesCount: 20, selectedCount: 1 }
```

The `useMemo` ran **113 times** during a multi-select of just 4 shapes!

---

### **Problem 2: Excessive Re-renders from Presence Heartbeat**

The `usePresence` hook triggers App re-renders every ~1 second:
```
👥 Visible users: 1
🎨 Current user color updated: #98D8C8
👤 Current user name updated: User
🏠 App render #129 → #130 → #131 → ...
```

During the multi-select test:
- **App rendered**: 185 times
- **Canvas rendered**: 113 times
- **Presence updates**: ~60+ times

Each presence update:
1. Updates App state
2. Triggers App re-render
3. Creates new callback references
4. Triggers Canvas useMemo to re-run
5. Recreates all 20 shape components
6. **Result**: 33 FPS instead of 60 FPS

---

## ✅ **The Fix**

### **Step 1: Stabilize Callback References**

Wrap all callbacks passed to `Canvas` with `useCallback`:

**Changed in `App.tsx`:**
```typescript
// ❌ BEFORE: Recreated on every render
const handleTextChange = async (shapeId: string, text: string) => { ... }
const handleColorChange = async (shapeId: string, color: string) => { ... }
const handleFontSizeChange = async (shapeId: string, fontSize: number) => { ... }
const handleZoomIn = () => { ... }
const handleZoomOut = () => { ... }

// ✅ AFTER: Stable references
const handleTextChange = useCallback(async (shapeId: string, text: string) => {
  // ...
}, [updateShapeText, showError])

const handleColorChange = useCallback(async (shapeId: string, color: string) => {
  // ...
}, [updateShapeColor, showSuccess, showError])

const handleFontSizeChange = useCallback(async (shapeId: string, fontSize: number) => {
  // ...
}, [updateShapeFontSize, showSuccess, showError])

const handleZoomIn = useCallback(() => {
  // ...
}, [])

const handleZoomOut = useCallback(() => {
  // ...
}, [])
```

## 📊 **Expected Outcome**

After this fix:
1. ✅ Callback references remain stable across App re-renders
2. ✅ Canvas `useMemo` only re-runs when shapes/selection actually changes
3. ✅ Shape components won't be recreated unnecessarily
4. ✅ FPS should improve significantly during multi-select

---

## 📝 **Key Learnings**

1. **`useMemo` is only useful if dependencies are stable**
   - Without stable callbacks, it re-runs on every render anyway
   
2. **Render logging is invaluable**
   - The console logs made the problem immediately obvious
   
3. **React DevTools would help too**
   - Next step is to use React Profiler to visualize this

4. **Performance issues are often cascading**
   - Presence updates → App re-renders → Unstable callbacks → Canvas useMemo → Shape recreation → FPS drop
