# Phase 4a: LangSmith Integration - Deferred to Phase 5

**Date**: October 18, 2025  
**Status**: ⏸️ **DEFERRED** to Phase 5  
**Reason**: Browser Compatibility Issue  

---

## 🔍 **What We Discovered**

LangSmith **cannot run in the browser** because it requires Node.js's `async_hooks` module (specifically `AsyncLocalStorage`), which is server-side only.

**Error Message**:
```
Module "node:async_hooks" has been externalized for browser compatibility. 
Cannot access "node:async_hooks.AsyncLocalStorage" in client code.
```

---

## 🎯 **Strategic Decision**

Since our Work In Progress CollabCanvas uses **client-side AI calls** (`dangerouslyAllowBrowser: true`), LangSmith integration is **deferred to Phase 5** when we:
1. Move AI API calls to a backend (Cloud Functions or Express API)
2. Remove `dangerouslyAllowBrowser: true`
3. Add LangSmith tracing in the backend code

This is the **correct approach** and follows industry best practices.

## 🔄 **Phase 5 Integration Plan**

When we move to backend (Phase 5), LangSmith integration is **trivial**:

### **Backend Code** (e.g., Cloud Function or Express endpoint):

```typescript
// backend/api/ai-command.ts
import OpenAI from 'openai';
import { traceable } from 'langsmith/traceable';
import { wrapOpenAI } from 'langsmith/wrappers';

// Initialize OpenAI with LangSmith (works perfectly in Node.js!)
const openai = wrapOpenAI(new OpenAI({
  apiKey: process.env.OPENAI_API_KEY, // Server-side env var
}));

export const executeAICommand = traceable(
  async (request) => {
    // Same logic as current openai.ts, but on server
    const completion = await openai.chat.completions.create({...});
    return completion;
  },
  { name: 'executeAICommand', tags: ['ai', 'canvas'] }
);
```

### **Frontend Code** (calls backend instead of OpenAI directly):

```typescript
// src/services/openai.ts (Phase 5)
export async function executeAICommand(request) {
  // Call backend API instead of OpenAI directly
  const response = await fetch('/api/ai-command', {
    method: 'POST',
    body: JSON.stringify(request),
  });
  return response.json();
}
```

## 💡 **Key Learnings**

### **What We Learned**:
1. **LangSmith is server-side only** - Requires Node.js environment
2. **Browser security** - Can't use `async_hooks` in browsers
3. **Work In Progress trade-offs** - Client-side AI is fast to develop, but limits observability tools
4. **Best practices** - Production apps should use backend for AI calls anyway

### **Why This Is Actually Good**:
- ✅ **Security**: Moving AI calls to backend is more secure (API keys not exposed)
- ✅ **Cost Control**: Server-side rate limiting prevents abuse
- ✅ **Observability**: LangSmith works properly in backend
- ✅ **Scalability**: Backend can handle more users efficiently
