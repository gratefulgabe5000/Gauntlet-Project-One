# ❌ useCallback Regression Analysis - What We Learned

**Date**: October 19, 2025  
**Status**: Reverted (Investigation in Progress)  
**Result**: 42% FPS regression (24 → 14 FPS)

---

## 📊 **What Happened**

We attempted to fix the multi-select FPS issue (24 FPS → target 60 FPS) by wrapping App.tsx callbacks with `useCallback` to stabilize Canvas's `useMemo` dependencies.

### **The Theory**
Canvas.tsx has a `useMemo` that depends on callbacks from App.tsx:
```typescript
const renderedShapes = useMemo(() => {
  // ... shape rendering ...
}, [
  shapes,
  selectedShapeIds,
  onSelectShape,           // From App.tsx
  onUpdateShapePosition,   // From App.tsx
  onTextChange,            // From App.tsx
  // etc.
]);
```

We thought: If App.tsx re-renders → callbacks get new references → useMemo re-runs → all shapes recreate → React.memo() fails → poor FPS.

**Solution attempted**: Wrap callbacks with `useCallback` to prevent new references.

---

## 📉 **The Results**

| Metric | Before useCallback | After useCallback | Change |
|--------|-------------------|-------------------|--------|
| **FPS** | 24 | 14 | ❌ **-42% (WORSE!)** |
| **Render Avg** | 24.9ms | 65.2ms | ❌ **+162% (SLOWER!)** |
| **Render Max** | 111ms | 476ms | ❌ **+329% (MUCH SLOWER!)** |
| **Dropped Frames** | 35 | 43 | ❌ **+23% (MORE!)** |

**Performance got dramatically WORSE instead of better!**

---

## 🤔 **Why Did It Get Worse?**

### **Theory 1: Dependency Chain Created More Work**
The useCallback dependency arrays created a chain of dependencies:

```typescript
handleColorChange = useCallback(..., [updateShapeColor, showSuccess, showError])
                                       ↓              ↓            ↓
                                    useCallback   useCallback   useCallback
                                       ↓              ↓            ↓
                                   More deps     More deps     More deps
```

If any dependency in this chain changes, the whole chain invalidates, potentially causing MORE work than before.

---

### **Theory 2: React's Reconciliation Got More Complex**
Adding `useCallback` might have made React's reconciliation algorithm work harder:
- More closures to track
- More dependency comparisons
- More memory allocations

The overhead of `useCallback` might have outweighed any benefits.

---

### **Theory 3: We're Not Fixing the Real Problem**
The regression proves our diagnosis was wrong. The real issue isn't callback stability - it's something else entirely:

**Possible real issues**:
1. App.tsx re-renders on every selection (even with useCallback)
2. The `shapes` array reference changes unnecessarily
3. Konva Layer forces re-renders regardless of memoization
4. Multiple state updates aren't batched

---

## 🎓 **Key Learnings**

### **1. Profile Before Optimizing**
We guessed at the problem instead of profiling. The regression proves we were wrong.

**Lesson**: Always use React DevTools Profiler to find the real bottleneck.

---

### **2. Optimizations Can Make Things Worse**
Not all performance techniques work in all situations. useCallback has overhead:
- Memory for closure
- Dependency comparison on every render
- Can break other optimizations

**Lesson**: Measure, don't guess. A "best practice" that makes things worse isn't a best practice.

---

### **3. Regressions Are Valuable Data**
The 42% FPS drop tells us our theory was fundamentally wrong. This is useful!

**Lesson**: Failed experiments teach us where NOT to look, narrowing the search.

---

### **4. Complex Dependency Chains Are Fragile**
Our useCallback implementation created a dependency chain:
```
App callbacks → useCallback deps → hook callbacks → their deps → ...
```

One change anywhere breaks the whole chain.

**Lesson**: Simpler solutions are more robust. Complexity breeds fragility.

---

## ✅ **What We Did Right**

1. **Documented everything** - Easy to understand what we tried and why
2. **Measured performance** - Screenshots prove the regression
3. **Reverted quickly** - Didn't waste time debugging a bad approach
4. **Learned from failure** - Now we know what NOT to do
