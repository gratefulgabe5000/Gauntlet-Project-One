## 🎯 **What Was Fixed**

The multi-select FPS drop (60 → 13 FPS) was caused by React.memo() not working properly. Even though we wrapped shape components with `React.memo()`, they were still re-rendering on every selection change because:

1. **New callback functions** were created on every render
2. **React.memo()** saw "new" props (even though data was the same)
3. **All shapes** re-rendered unnecessarily

## 🎯 **How This Works**

### **Dependency Array Magic**

The `useMemo` hook only re-creates shape elements when one of these dependencies changes:

- `shapes` - Shape data changed (added/removed/modified)
- `selectedShapeIds` - Selection state changed
- Callback functions (onSelectShape, onDragStart, etc.)

### **Selective Re-rendering**

**When you select a shape**:
- ❌ **Before**: All 20 shapes re-render → 13 FPS
- ✅ **After**: Only 2 shapes re-render (the one selected + the one deselected) → 60 FPS

**Example with 20 shapes**:
1. User selects shape #5
2. `useMemo` runs because `selectedShapeIds` changed
3. Shape #5 gets new props (`isSelected: true`)
4. All other shapes get **same props** as before
5. React.memo() skips re-rendering shapes #1-4 and #6-20
6. Only shape #5 re-renders → **60 FPS maintained!** 🎉

## 🎓 **Key Learnings**

### **1. React.memo() Needs Stable Props**
React.memo() only works if props are referentially stable. Creating new callback functions on every render defeats its purpose.

### **2. useMemo for Component Arrays**
When rendering arrays of components, wrap the `.map()` in `useMemo()` with proper dependencies to stabilize prop references.

### **3. Dependency Arrays Matter**
The dependency array tells React when to re-create the memoized value. Too few dependencies = stale data. Too many = no optimization.

### **4. Set + useMemo = Performance Win**
Combining `Set` for O(1) lookups with `useMemo` for stable props gives dramatic performance improvements.
